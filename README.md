# MNIST Digit Recognition on STM32N6570-DK

This project runs a real-time handwritten digit classifier (0–9) entirely on the **STM32N6570-DK** Discovery Kit — no PC, no cloud. The onboard IMX335 camera captures a frame, a preprocessing pipeline normalises it, and the **Neural-ART NPU** classifies the digit in under 5 ms. The result is shown on the LCD and printed over UART.

**The system is fully functional.** All 10 digits were tested and recognised with high confidence. The only practical requirement is that the camera is held **10–15 cm** from the digit — closer than you might expect, but stable and reliable at that distance.

---

## How to Run

### Prerequisites

- [STM32CubeIDE v1.17.0](https://www.st.com/en/development-tools/stm32cubeide.html)
- [STM32CubeProgrammer v2.18+](https://www.st.com/en/development-tools/stm32cubeprog.html) — must be installed at the default path
- STM32N6570-DK board connected via USB-C on **CN6** (ST-LINK port)
- PowerShell (Windows)

---

### Step 1 — Build

1. Open **STM32CubeIDE**
2. `File → Open Projects from File System` → select the `Application/STM32CubeIDE` folder
3. `Project → Build All`

This produces `Application/STM32CubeIDE/Debug/Project_sign.bin` (signing is automatic as a post-build step).

---

### Step 2 — Flash

Set the board boot switch to **DEV mode**, then open a PowerShell terminal in the project root.

**First time ever (flash everything):**
```powershell
.\flash.ps1 -Weights
```
This flashes the bootloader (FSBL), the application, and the model weights to NOR flash. Takes ~30 seconds.

**After rebuilding the application (code changes only):**
```powershell
.\flash.ps1 -AppOnly
```

**After changing the model only:**
```powershell
.\flash.ps1 -Weights
```

---

### Step 3 — Boot

After flashing completes:
1. Set the boot switch to **BOOT FROM FLASH**
2. Power cycle the board (unplug and replug USB)

The board starts immediately — no SD card or host connection needed.

---

### Step 4 — Use it

Hold a handwritten digit in front of the camera:
- **Distance: 10–15 cm** — this is critical, the camera FOV is narrow at 32×32 resolution
- **Black marker on white paper**, centred in frame, no shadows
- The digit should fill most of the frame

The LCD displays the predicted digit and confidence. UART output (115200 baud, 8N1 on USART1) prints:
```
[3] 99%  (4ms)
[7] 94%  (4ms)
[1] 87%  (4ms)
```

Predictions below **70% confidence** are automatically discarded — you will see no output rather than a wrong answer.

## How It Works

The camera outputs a 32×32 RGB frame. Before feeding it to the NPU, two preprocessing passes run in software:

1. **Inverted grayscale** — converts to luminance and inverts so dark ink becomes bright, matching the MNIST convention (white digit on black background).
2. **Adaptive background suppression** — finds the min/max pixel values in the frame, zeroes out everything below the midpoint (background), and rescales the rest to [0, 1]. This eliminates lighting gradients that caused false detections.

The int8-quantised CNN then runs on the Neural-ART NPU:

```
Camera → 32×32 RGB → grayscale invert → adaptive suppress → int8[3072]
    → Neural-ART NPU (28 394 params, weights in NOR flash)
    → int8[10] → dequantise → argmax → reject if < 70%
    → LCD + UART
```

### Model

| Property       | Value                                                    |
|----------------|----------------------------------------------------------|
| Architecture   | 3× Conv2D + GlobalAvgPool + 2× Dense                     |
| Parameters     | 28 394 — weights: **27.6 KB** int8 (was 110.9 KB fp32)   |
| Input          | 32 × 32 × 3 int8 (scale = 1/255, zero\_point = −128)     |
| Output         | 10-class int8 → dequantised float32                      |
| Training       | MNIST + data augmentation (rotation, shift, zoom, shear) |
| Export         | Keras → ONNX → STEdgeAI per-channel int8 → Neural-ART    |
| Inference time | < 5 ms on Neural-ART NPU @ 1 GHz                         |

## TEST_MODE

To verify the model without the physical setup, set `#define TEST_MODE 1` in `Application/Src/main.c`. The board runs inference on 10 synthetic images from `digits.h` instead of the camera, printing `OK` or `WRONG` for each — useful after reflashing to confirm everything is working.

---

## Test Results

All 10 digits (0–9) were successfully recognised in both test scenarios:

- **Handwritten on paper** — black marker on white paper, held 10–15 cm from the camera
- **Digits on screen** — Notepad or any app, black text on white background, held 10–15 cm from the camera

Recognition was reliable across all digits in both cases. No formal per-digit accuracy benchmark was conducted; results are based on empirical testing during development.

> **Tip for digit 7:** write it without the horizontal bar through the stem. The model was trained on MNIST which uses the plain unbarred style — a barred 7 may not be recognised.

---

## Known Limitations

- **Camera must be 10–15 cm away** — at greater distances the digit is too small relative to the 32×32 input resolution.
- Background suppression assumes the digit is darker than the background — inverted or low-contrast scenes will not work.
- Digits partially out of frame or strongly tilted produce unreliable output.
